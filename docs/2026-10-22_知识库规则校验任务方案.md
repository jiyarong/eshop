# 任务一：建立可追溯、可验证的平台知识规则与结论输出机制

整理日期：2026-10-22。依据：用户提供的两段会议记录、当前 GBrain 获准数据源中的知识页和本项目约束。

本文是建议立项方案；未修改知识库、业务代码或数据库，未执行平台操作。职责和工期均为建议，不代表与会人员已确认。

## 1. 任务定义

**将平台费用和供货文档整理为带适用条件、版本、原文证据、计算方式、例外及验证记录的规则，让 AI 对具体业务问题输出可复查的结论。**

“全面”应指对约定问题范围的规则、例外、附件和依赖覆盖完整；“正确”应指适用条件匹配、计算可复现、证据可追溯；“无歧义”应指边界明确且未知项明确标记。不能承诺模型永不出错，也不能把所有模型都同意等同于事实成立。

与送仓任务的关系：先提供送仓所必需的分类、包装、准入、计费规则；其余费用规则分批扩展。任务二的数据审计可并行，自动费用推荐以任务一的已验证规则为输入。

## 2. 会议共识与需要调整的做法

| 会议内容 | 落地解释 |
|---|---|
| 平台文档复杂，AI 对大小件分类和组合规则存在误解 | 优先梳理业务对象、国家、履约模式、版本和条件，不能只换 Prompt |
| 尝试多轮问答或多 Agent 校验 | 采用独立提取、反例审查、确定性测试、账单回放和人工裁决的闭环 |
| 利用真实利润、广告、配送费用反查 | 对可比的原始费用项目逐项回放，不只核对最终利润 |
| 先整理打托相关费用给人工校验 | 第一批范围限定为送仓与打包规则，形成规则清单、冲突清单和验收案例 |

需要明确：实际账单是校验信号，不是可任意推导规则的唯一依据。没收仓储费，可能是免费期、促销、未结算、统计范围不完整或费用映射遗漏，不能直接证明“永久免费”。

## 3. 本次知识库核查发现的具体问题

### 3.1 Ozon 分类汇总存在版本差异

旧页 `playbooks/ozon-wb-fulfillment-rules` 的检索内容将 45–220 / 32–120 / 32–80 cm 汇总为 KGT；较新页 `sources/ozon/seller-guide/kgt/fbo/postavka-kgt-fbo` 分列“不可分拣商品”和“大件商品”。因此不能继续拿旧汇总中的单张表直接给所有 SKU 分类。

分类对象还必须是**带最终销售包装的单件商品**；外箱用于箱送、装托几何和运输重量，托盘又有独立限制。大外箱不代表箱中每件商品都是大件。

新页本身的不可分拣和大件区间仍有重叠表达。正常件边界、任一维度触发还是全部维度触发、重量优先级、尺寸排序，需要结合供货规程、原文和平台商品标签验证。项目现有分类约定可以作为软件当前行为记录，不能反过来证明平台原文没有歧义。

证据：
- `sources/ozon/seller-guide/kgt/fbo/postavka-kgt-fbo`
- `sources/ozon/seller-guide/fbo/gruzomesta-i-podgotovka-k-otgruzke/k-kakoi-zone-otnositsya-tovar`
- `playbooks/ozon-wb-fulfillment-rules`

### 3.2 同一个“托盘限制”必须区分履约模式和点位

知识页汇总的 Ozon FBO 与 FBS 托盘高、重量上限不同；WB 又区分箱式、单一托盘、按件托盘和收货点。不能形成一个跨平台通用的“最大托盘重量”常量。

规则必须表达为：某平台、某卖家合同范围、某履约模式、某收货点、某货位类型、某日期下，对哪个对象适用的重量或高度限制。若只验证了俄罗斯 FBO 场景，不能自动推广到白俄罗斯卖家合同。

证据：`platform-guides/wildberries-ozon-pallet-shipping-rules-and-fees`、`sources/wb/seller-guide/weight-and-dimensional-restrictions-on-different-sales-models`。

### 3.3 汇总页与细则对 WB 费率锁定表述不同

汇总页将处理、仓储和配送费率列入锁定范围；完整《第 1 步。创建入库》写明配送和存储系数固定 60/90 天，**处理系数不会固定**。

这需要按“基础费、系数、具体服务、供货日期”分别核查，不应输出笼统的“所有费用锁定 60 天”。在冲突裁决前，相关规则标记为待核实，不直接进入自动报价。

证据：`platform-guides/wildberries-ozon-pallet-shipping-rules-and-fees` 第 7.4 节，与 `sources/wb/seller-guide/step-one-fbw-shipments-creation` 第 4 步。

### 3.4 日期字段不能直接用作规则生效日

本次返回的多个页面带 `effective_date_source: fallback`，工具明确说明这可能是页面创建或导入日期。页面也可能同时包含历史、当前和未来版本。

必须分别记录：官方发布日期、抓取日期、人工复核日期、条款生效起止、计费采用的事件日期。2026-10-30 版本对 2026-10-22 仍是未来版本；预计交货在 10 月 30 日后，也应根据条款规定的锁价或计费事件选择版本，不能简单一律按查询日。

### 3.5 规则藏在附件和特殊范围中

仓储免费期、促销品类清单、路线费率和跨境禁限品，可能位于页面链接的 Excel 或其他附件。只读取正文不能证明已经掌握完整规则。

“不同 SKU”“不同存放区”“不同目的集群”“不同供货单”是不同维度，不能把它们合并为“混托”。同样，“没有额外分拣费”也不等于“运输、点位处理和仓储全部免费”。

证据：`sources/ozon/seller-guide/commissions-tariffs/commissions-tariffs-ozon/rashody-na-dop-uslugi`、`sources/ozon/seller-guide/prodaji-i-postavki-v-drugie-strany/postavki-na-sklady-v-drugie-strany`。

### 3.6 完整正文复核补充：不能沿用汇总中的确定语气

- 费用帮助页的仓库/分拣中心点位处理费有表格显示“—”，而汇总页直接写为0。破折号是否代表不另收、包含在其他服务或不适用，保存正文没有解释，不能无条件转成零值。
- `sources/ozon/seller-guide/commissions-tariffs/legal-information/full-actual-commissions` 页首写明版本自2027-01-15起生效，并包含多个2026年日期的补充。其2.2节又有10月7日生效表述，与帮助页货位处理的10月1日分段不同。必须按具体条款及当时有效归档核对，不能仅因页面名叫“完整现行费用”就认定全页今天有效，也不能机械认定帮助页覆盖合同。
- 免费仓储正文写明同SKU免费期机制“可以累加、优先消耗较早供货”；这不能证明多项促销可以相加。9月22日至12月31日接收供货的特殊期限只链接Excel，具体天数与排除项仍需读附件。
- Fashion按组成分拣优惠按申请创建日期分段；免费仓储特殊资格按接收日期分段。不同服务使用不同日期锚点，不能只存一个笼统“供货日期”。Fashion按组成分拣优惠不能推广为跨存放区分拣或组成错误修正也免费。
- 存放区页在450/320/320mm等号边界有区间重叠，大件第三维还重复写“宽度”。不得静默修正文案后当作已确认官方算法；应回到俄文原页、合同和平台商品标签核查。
- 旧playbook的复核期截至2026-10-18，本次已超过，应列为待复核材料，不能因仍可检索就当作有效执行依据。

这些结论来自保存正文的完整读取；保存页是中文加工文本，本次没有逐项核对俄文在线原页，引用时不能称为“俄文原文直引”。

## 4. 知识结构：保留原文、规则化、面向问题输出

不要求重建现有 GBrain。优先利用现有 source、platform-guide、playbook 页面及其关联，补齐以下结构。

| 层次 | 保存内容 | 使用要求 |
|---|---|---|
| 原始证据 | 官方原文、完整表头与脚注、附件、URL、文件哈希、抓取时间 | 原始版本保留；中文翻译可追溯到原文位置 |
| 规则条目 | 原子规则、适用条件、公式、优先级、例外、版本、验证状态 | 一条规则能够独立说明何时适用、如何判断 |
| 场景结论 | 针对具体 SKU、账号、路线、日期的判断和计算过程 | 明确命中规则、输入、缺失项、结论可信范围 |

知识页继承原文权威性必须有证据链。标记 `source_tier: official` 但 `trust_tier: agent_written` 的中文整理，仍是加工材料；两个整理页引用同一份原文，不构成两份独立证据。

## 5. 每条规则的最小字段

| 字段组 | 必须记录的内容 |
|---|---|
| 身份与状态 | rule_id、版本、draft/review_required/verified/superseded |
| 范围 | 平台、卖家注册国/合同体系、发货国、目的国、店铺适用资格、FBO/FBS/FBW、品类 |
| 场景 | 直送/越库、交货点、目的集群/仓、供货类型、普通货位/运输货位 |
| 业务对象 | 单件销售包装、外箱、托盘、货位、供货单、批次、SKU日库存 |
| 前置条件 | 尺寸/重量/标签/货位组成/活动资格，包含条件之间 AND/OR 关系 |
| 边界 | 单位、三边排序、含不含边界、含不含托、是否包含包装重量 |
| 计算 | 计费基数、币种、含税状态、取整顺序、最低收费、封顶、数量乘法所在层级 |
| 时间 | 发布与抓取时间、生效起止、选版本使用的事件，例如建单/交货/验收/计费日 |
| 例外与组合 | 免费期、促销、优先级、可叠加或互斥、替代关系；原文未明确时记待核实 |
| 证据 | 精确 slug、原文 URL、段落/条款/附件 Sheet与单元格、短原文、内容哈希 |
| 验证 | 官方样例、边界用例、实际账单样本、误差、复核人、复核日期、失效条件 |

示例只描述结构：`规则甲：在已确认适用的 Ozon FBO 越库场景，逐托计算路线计费体积，采用条款规定的向上取整和最低体积，再乘该路线、日期的费率。` 不能把俄罗斯汇总中的最低值或费率无条件写入所有白俄罗斯账号的全局规则。

## 6. AI 校验闭环

建议用 4 类职责，先通过逻辑独立的提问和证据输入实现；不要求一开始配置大量 Agent。

1. **证据提取者**：从完整原文及附件提取规则，保留原文条件，不自行补充阈值。
2. **反例审查者**：独立检查规则遗漏、版本错配、边界歧义和国家/模式混用，构造能推翻结论的案例。
3. **计算与账单校验者**：运行确定性案例和项目只读账单回放，输出差额，不能为了贴合账单擅改费率。
4. **裁决与发布者**：汇总冲突；无证据时保留待核实；关键歧义提交业务人员复核，批准后才发布新版本。

流程：

```text
业务范围与规则覆盖清单
  → 原文及附件收集
  → 独立提取规则
  → 反例、冲突、覆盖审查
  → 确定性测试 + 财务回放
  → 已证实 / 缺证据 / 有冲突
  → 人工裁决关键项
  → 发布规则版本
  → 文档更新或账单异常触发重新验证
```

建议每轮只处理新增证据和未解决问题；常规最多 3 轮作为成本控制，仍未解决则明确输出阻塞项并转人工，不以“多数同意”结束。完成条件是关键规则有证据、通过规定测试、没有未解决的执行歧义；不是达到问答轮数。

模型可辅助解释、发现遗漏和设计测试。尺寸分类、费用公式、日期选择、库存守恒、整数箱数，交由确定性计算器执行。

## 7. 财务反查怎样才有效

### 7.1 样本选择

建立按业务范围分组的人工核准样本，至少覆盖：

- 普通件、不可分拣、大件及边界尺寸/重量。
- 箱、单 SKU 托、同区混 SKU 托、不同存放区及组成异常。
- 免费仓储到期前后、促销资格有无、入库跨费率切换日。
- 直送/越库、不同交货点、有效与无效路线。
- 取消、退货、费用冲正、结算延迟和零活动期间。
- 卖家合同范围差异；白俄罗斯与俄罗斯样本分开。

只按一个总利润值匹配不能验收规则。要把平台原始财务项目映射到相同账号、SKU、供货/订单、服务期间、币种和规则版本，逐项比较。

### 7.2 分层对账

```text
原始计费记录
 → 费用项目与业务对象归属
 → 规则公式的输入与预测费用
 → 原币金额差额
 → 税与汇率换算
 → 周报/订单报表合计
```

项目已有周报和订单报表可辅助定位，规则校验仍优先读取 `raw_*` 原始费用，避免报表分摊、结算周、跨 SKU 分配掩盖错误。

差异分类为：数据缺失、关联错误、计费期间错位、规则范围不符、版本错误、取整问题、活动折扣、平台调整、尚未解释。不得添加“调整系数”掩盖差额。

账单可验证已发生场景，不能证明未发生场景的规则，也不能从一个免收费案例推导所有品类和所有时间免费。

## 8. 结论输出契约

每次回答费用或准入问题，按以下顺序提供：

1. **结论**：可执行、不可执行、附条件可执行或暂不能判断。
2. **适用范围**：平台、账号合同/卖家国、履约模式、商品、路线、相关日期。
3. **已知输入**：单件包装尺寸重量、数量、货位、费率和库存的来源及时间。
4. **命中规则与计算**：公式、取整过程、收费项目与证据定位。
5. **例外及冲突**：促销、免费期、后台资格、原文不一致。
6. **缺失信息与影响**：缺什么、影响金额还是准入、由谁补齐。
7. **复核记录**：知识版本、复核日、报价有效范围和执行前需要更新的动态信息。

问答不全时：不影响结论的缺失项只列说明；影响分类、可接受性或收费版本的缺失项必须阻止确定性结论。未知费用不能补 0，不能把“估算”展示为“完整总成本”。

## 9. 实施拆分与验收

| 子任务 | 主要交付 | 验收标准 | 建议牵头 |
|---|---|---|---|
| K1 范围与术语统一 | 问题清单、对象和收费项目词典 | FBO/FBS、单件/外箱/托盘、集群/交货点不混用 | 夏元胤组织，皮特复核业务 |
| K2 规则盘点与冲突表 | 原文、附件清单及规则条目 | 所有执行关键规则都有证据位置；缺失附件显式列出 | 皮特 |
| K3 校验闭环原型 | 独立提取、反例、裁决流程与输出模板 | 相同问题可复现；冲突不被自动抹平 | 夏元胤 |
| K4 计算与财务案例 | 人工标准样本、边界测试、只读回放结果 | 标准样本分类全部正确；金额按规则精度/官方取整核对；残差逐项解释 | 皮特与开发人员 |
| K5 发布与持续维护 | 已验证规则版本、变更及过期机制 | 未验证规则不能参与自动执行；旧版本可追溯；变更触发回归 | 胡源确认制度和责任 |

验收建议：第一批先收敛送仓涉及的关键规则，数量以盘点结果为准，不以“凑够几十条”为目标。可量化检查规则证据覆盖率、边界用例正确率、冲突阻断率、账单差异解释率与过期规则误用次数；执行关键项要求全覆盖，其余清楚列为后续范围。

## 10. 已知限制与后续核实

- 本次读取的是知识库快照，没有访问 2026-10-22 平台后台或实时账号能力，不能声称已核实当日路线、费用和预约。
- 多个页面为 Agent 加工材料；正文涉及的官方 Excel 未在本次逐表解析，免费期和品类例外不能宣称已完整确认。
- 指定 `ozon-ru` 数据源返回无授权；本次按工具建议在当前连接允许的数据源中查询，实际返回为 `default`，未获得额外授权。
- 部分检索报告向量超时并降级为关键词，实体引用索引也未完整扫描；检索不到不能解释为规则不存在。
- GBrain `think` 因服务端未配置综合模型未执行综合。本方案由当前会话依据已读取页面和会议独立整理，不能把该工具返回视作额外验证意见。
