# Ozon 商品上架自动化接口矩阵

当前实现使用 Ozon Seller API 的以下版本。所有请求由服务端 `RawOzon::OzonClient` 发出，Agent 和页面不接触 `Client-Id`、`Api-Key`。

| 用途 | 方法 | 路径 | 结果 |
| --- | --- | --- | --- |
| 全量创建/更新 | POST | `/v3/product/import` | 异步 `task_id`，每批最多 100 个商品 |
| 导入状态 | POST | `/v1/product/import/info` | `pending`、`imported`、`failed`、`skipped`；未知状态按失败保留 |
| 属性增量更新 | POST | `/v1/product/attributes/update` | 不能删除已存在属性，删除或完整替换需重新导入 |
| 全量图片替换 | POST | `/v2/product/pictures/import` | 请求必须包含最终保留的完整图片集合 |
| 图片状态 | POST | `/v2/product/pictures/info` | 图片任务状态 |
| 价格 | POST | `/v1/product/import/prices` | 保留 `price`、`old_price`、`min_price` 与币种 |
| 库存 | POST | `/v2/products/stocks` | 使用 `product_id`、`warehouse_id`、`stock`、`quant_size` |
| 商品详情/审核 | POST | `/v3/product/info/list` | 回读 `product_id`、`sku`、审核及校验字段 |
| 商品配额 | POST | `/v4/product/info/limit` | 提交前检查额度 |
| 角色权限 | POST | `/v1/roles` | 启用写操作前确认账号权限 |

请求必须带 `Client-Id`、`Api-Key`、`Content-Type: application/json`。429 需要优先读取 `Item-Retry-After`，并记录 `Item-Rate-Limit-Remaining`；普通 `Retry-After` 作为兼容回退。Ozon 没有通用商品预校验接口，预校验由本地类目/属性规则完成，任务错误和商品详情回读是最终结果。

本地绑定只在导入成功且详情回读返回 `id`、`sku` 后创建或更新 `Ec::SkuProduct`：`product_id` 保存 Ozon 商品 ID，`platform_sku_id` 保存 Ozon SKU，`offer_id` 保存卖家 offer。
