# AI 评测首版：使用与验收

## 入口和启用

入口为 `/admin/ai_evals`，需要 `manage_users` 权限。全部页面采用项目现有 Rails/ERB/Turbo 体系，文案支持中文、英文、俄文。

新增迁移是 `20261015114755_create_ai_eval_records.rb`，候选数据后台生成另需 `20261016022220_create_ai_eval_patch_suggestions.rb`。当前仅已迁移 test 数据库；在目标环境部署代码并正常执行 `bin/rails db:migrate` 后启用。候选数据生成和评测异步运行均使用已有 Solid Queue/default 队列，需要现有 `bin/jobs` worker 运行。此说明不表示已部署。

```text
真实 SKU → 只读采集 / 导入快照
          → 编辑 Patch → 校验与字段 diff
          → 填写 Oracle → 人工批准、版本锁定
          → 配置运行 → 异步模型调用 / 等待 Activepieces
          → 断言得分、证据、基线差异 → 人工复核
```

## 数据集编辑

在首页输入真实 SKU 和采集日期。采集读取当前应用数据库，不执行平台 HTTP、同步、生产诊断或 Planner。`as_of` 只能控制原 Query 支持的历史查询，不能把当前 Listing/当前状态还原成某个过去时刻；严格历史回放应导入当时保存的快照。

快照保留完整 V3 响应信封，例如：

```json
{
  "data": {
    "schema_version": 3,
    "sku_code": "JJ005-6",
    "period": {"as_of": "2026-10-15", "time_zone": "Asia/Shanghai"},
    "inventory": {"current_inventory_info": {"values": {"book_stock": 20}}}
  }
}
```

上例仅展示路径，实际快照包含原有其他字段。导入对象格式为 `{"manifest": {...}, "documents": {"v3/inventory_context.json": {...}, ...}}`。manifest 必须同时包含字节 checksum 和规范化内容 checksum；后者兼容 PostgreSQL JSONB 的对象键顺序。

创建案例后编辑 JSON Patch；无需重写整个 SKU。比如更改现有库存值：

```json
{
  "date_mode": {"type": "none"},
  "patches": [{
    "target": "v3/inventory_context.json",
    "op": "replace",
    "path": "/data/inventory/current_inventory_info/values/book_stock",
    "value": 20,
    "reason": "模拟低库存"
  }],
  "derived_fields": {
    "mode": "recompute",
    "paths": ["/data/inventory/current_inventory_info/values/strict_forecast_cover_days"]
  },
  "oracle": {}
}
```

先点击“校验并预览差异”，确认业务相关字段全部一致，再保存。库存、生命周期、分店铺明细可能存在相同事实的多个表达；首版不会推断所有依赖关系。自动重算只支持三项库存覆盖天数，其他依赖需显式 Patch。新增未知字段、改变 JSON 类型、引入未知 Listing/店铺/Product ID 会被拒绝；`null` 保持缺失语义。

Web Agent 辅助区允许选择启用的 Web Agent，输入场景后点击“生成候选数据”。请求只保存任务并加入后台队列，立即返回编辑器；提交时未保存的 JSON、案例标识、所选 Agent 和场景均会保留。页面显示排队/生成/完成/失败状态，点击“刷新进度”查看结果。生成成功并通过物化校验后回填 Patch、Oracle 草稿及字段差异；模型或校验失败时显示错误，保留原输入，可重新提交。

生成使用所选 Agent 的模型参数和受控 Prompt，不执行其外部工具。后台任务不会保存或批准案例，新案例也不会因生成候选数据而创建正式案例记录；修改已批准版本时仍需另行保存为新草稿并人工批准。

批准版本和原始快照不可修改；编辑已批准案例会生成新版本。Oracle 更新同样需要新版本，已有运行保留原数据和答案。

## Oracle 与评分

每个启用的评测项目都需要非空且可执行的断言。推荐按业务含义校验结构化字段，不逐字比较诊断全文。示例：

```json
{
  "diagnosis": {
    "threshold": 90,
    "assertions": [
      {"id":"critical_stockout","path":"$.events[0].severity","operator":"eq","expected":"critical","severity":"critical","weight":3,"evidence":"库存覆盖不足，按所选规则阈值判断"},
      {"id":"has_evidence","path":"$.events[0].simple_context","operator":"exists","expected":true,"weight":1}
    ]
  },
  "planner": {
    "assertions": [
      {"id":"replenish","path":"$.plans[*].operation","operator":"include","expected":"increase","weight":2},
      {"id":"deadline","path":"$.plans[0].execution_deadline","operator":"eq","expected":"2026-10-19","shift_dates":true,"weight":1}
    ]
  }
}
```

示例断言不能直接当作真实 SKU 的已审核答案；严重级别、动作方向和证据应按具体场景和规则独立核定。数组顺序不稳定时使用 `[*]`、`include`、`subset`，或明确限定运行规则，避免依赖不必要的位置顺序。

支持 `eq/one_of/include/exclude/exists/numeric_close/range/subset/jsonpath`；JSONPath 仅允许字段、索引、通配符，不执行脚本和过滤表达式。`semantic_fact` 未接入 Judge，会阻断批准。空断言、零总权重、重复 ID、非法阈值或算子也会阻断，不会默认为满分。

默认通过条件为得分至少 90、critical 断言全通过、安全门禁全通过。`category_weights` 可在各项目中显式配置；不配置时按断言 `weight` 计算。`exists` 区分字段不存在与显式 `null`；要验证非空证据，还应补内容断言。内置诊断工具已要求非空 `simple_context`。

运行状态分别表达：`passed` 达标、`failed` 完整执行但业务答案不符、`blocked` 数据/工具/引用/评分门禁不满足、`error` 模型或基础设施异常。多个项目中任一阻断就不能将整个运行判为通过。

## 时间与独立评测

- 留空运行锚点：使用案例固定日期。`historical_replay` 保持此日期。
- `online_synthetic` 可指定新锚点；带自然周的快照只接受 7 天整数倍平移。星期与原快照保持一致。
- 同步平移原结构的日期字段、固定 Planner/Evaluation 输入和已知指标日期键；不改 SKU、P0/P-1 标签或业务文案中的日期。
- Oracle 的日期默认固定。断言设置 `shift_dates: true` 后，仅其 `expected` 中严格 ISO 日期/时间值随运行相对案例日期平移。
- V3 Markdown 从变异响应重建。补充 Listing 文本若包含日期，第一版拒绝平移，需重新采集。
- Evaluation 限制到 `min(execution_deadline, as_of - 1)`，动作、已知指标周期与诊断证据超过该截止日会被拒绝。没有动作必须 `inconclusive`，没有指标为 `insufficient_data`。

Diagnosis 使用所选启用规则当前的 Prompt/配置；不选规则时按快照 grade/stage 选择适用规则。显式选择规则与生产人工诊断一致，可用于测试条件外的单条规则。规则包含暂不支持的 Listing 图文上下文时返回 `blocked`。

Planner 同时勾选 Diagnosis 时默认使用本次捕获事件；单测 Planner 则在案例的 `planner_input.events` 提供固定事件。需要 `id/sku_code/sub_agent_id/severity/is_latest/created_at` 及原事件证据，事件须属于当前 SKU/当前上海自然周；`info` 和建议动作事件不作为依据。通过服务调用可设置 `settings.planner_source=fixed`，在组合运行中也强制使用固定输入。

固定 `planner_input/evaluation_input` 中的日期按原快照日期填写，物化时应用案例与运行的总平移量；Oracle 的日期则按案例默认日期填写。这两种作者基准应在编辑时区分清楚。

Plan Evaluation 在案例 `evaluation_input` 中提供原格式 `plan/actions/metrics/diagnosis_context`，可选 `concurrent_actions`。这是固定证据评测，不会执行生产历史评估前置流程，也不重跑业务指标 Query。不扫描自然语言里的日期，不推断无日期数值的时间归属。

模型适配器复用生产问题模板和工具 schema，但对话与工具结果仅保存在 Eval 运行中。`save_sku_event/save_sku_plan` 返回捕获结果；禁止生产工具和跨 SKU 写入。它评测 Agent 的上下文判断及工具输出，不代表整条生产流水线回放。

## Activepieces 首版接入

包含 Activepieces 的运行完成物化后进入 `awaiting_activepieces`。独立 Eval Flow 的 HTTP 基址应指向该运行：

```text
https://<ERP_HOST>/ai/eval_runs/<RUN_ID>/ai/v3/sku/
```

后接原来的 `base_context.json`、`inventory_context.json`、`profit_context.json` 等。响应原封保留 `data`，因此现有 Data Mapper 路径无需改变。请求需具有 `manage_users` 权限的 API Key，使用已有安全变量/连接保存，不写入流程源码、快照或回传。

HTTP 返回 `X-AI-Eval-Fingerprint` 和 `X-AI-Eval-Run`。所有步骤必须使用相同 run 基址，禁止混用真实 API 和另一案例的输入。仅等待阶段供数，结束后不再开放。文件快照另有 `/ai/eval_snapshots/<SKU>/<DATE>/ai/v3/sku/<section>.json?case_key=...`，用于 CLI 固定包联调；Web 运行应优先使用 run 地址。

首版提供手工导入，格式为：

```json
{
  "execution_status": "SUCCEEDED",
  "metadata": {
    "external_run_id": "<ACTIVEPIECES_RUN_ID>",
    "run_id": "<EVAL_RUN_ID>",
    "fingerprint": "<MATERIALIZATION_FINGERPRINT>",
    "sku_code": "JJ005-6",
    "as_of": "2026-10-15",
    "time_zone": "Asia/Shanghai"
  },
  "steps": [],
  "output": {"status": "critical"}
}
```

页面填写同一个外部 Run ID 并导入。系统核对身份和输入指纹后按 `oracle.activepieces.assertions` 评分；错配和重复导入会拒绝。`steps` 应附关键 Router/HTTP/输出步骤证据，Oracle 可针对规范化 `output` 校验分支、指标、null 与来源。

来源明确保存为 `manual_import`。指纹一致只能证明回传声明与本次输入匹配，不能独立证明外部流程真实执行过；该结果不能标成已验证线上端到端。首版未自动连接 MCP 执行和读取 run。部署后还需创建独立只读 Eval Flow，依次 validate、完整 test、读取 run，核对实际 HTTP、关键分支与最终结果，才能完成线上端到端验收。禁止修改/发布生产 Flow 来绕过这一步。

## 基线和复核

基线必须是同一快照、同一案例版本、同一有效日期和同一 Oracle 的已结束运行，并包含当前评测项目。结果保存断言级 Expected/Actual、critical 失败、得分维度、基线新增失败/恢复，以及模型请求、工具调用、usage、Prompt 指纹和外部 Run ID。首版未聚合模型费用和多次随机运行的稳定性统计。

人工复核可标记“真实缺陷 / Oracle 需要更新 / 案例错误 / 可接受差异”，保留人员和时间；复核不改写原始自动评分。更新答案从案例新版本开始。
