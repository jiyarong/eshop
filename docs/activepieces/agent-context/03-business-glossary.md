# 业务口径和不变量

这是给外部 Agent 的最小业务词典。涉及具体公式时，以目标流程的 README、规则模块和测试为准。

## 时间和周期

- 计划周期按 `Asia/Shanghai` 的自然周计算，周一至周日为一个周期。
- API 上下文的日期事实来自 `data.period.as_of` 和 `data.period.time_zone`。
- 利润和销售漏斗的 `P0` 不一定代表同一自然周：库存流程中利润通常使用上一个完整周，漏斗可能使用当前周。必须保留各板块自身的周期定义。
- 周数组按 `period_key`（例如 `P0`、`P-1`）读取，不能假设数组顺序。

## 缺失和证据

- 缺失数据不是零。缺少必要指标时输出 `insufficient_data` 或等价降级状态。
- `available_metrics` 是字段可用性的白名单；不在其中的指标不能参与计算。
- 结论必须能追溯到来源接口、字段路径、计算规则和观察周期。
- 信息性事件不能直接作为计划依据；诊断、计划、动作和评估的状态分别表达不同含义。

## 库存和补货

- `book_stock` 是账面可用库存，`incoming_quantity` 是采购中或在途库存。
- 普通覆盖通常是 `book_stock / daily_sales_velocity`；含采购覆盖通常是 `(book_stock + incoming_quantity) / daily_sales_velocity`。如果上下文已经提供覆盖指标，应优先引用并保留来源，不要无条件用除法重算。
- 断货校准可以使用有效历史周，但应跳过缺失周和低库存周，并保留样本证据。
- 全链覆盖达到目标天数时建议补货量可以为 0；数据不足时建议量应为 `null`。
- `CLR`（清仓）禁止生成补货预警和采购建议。
- FBS 是履约库存口径，不能据此推断官方仓仓储费；多个 Listing 可能共享同一物理库存，不能简单相加后再次从账面库存扣除。

## Grade 和 Stage

- Grade 常见值为 `S`、`A`、`B`、`C`；Stage 常见值为 `NEW`、`GRW`、`MAT`、`CLR`。
- Grade 影响数据门槛、增长压力和目标覆盖；Stage 影响目标覆盖和是否允许补货。
- 不能用缺少 Grade/Stage 的记录自动推断最安全或最高优先级策略。

## 运营闭环

- Diagnosis 产生诊断事件，Plan 产生计划，Action 记录实际动作，Evaluation 评估观察窗口效果。
- “没有动作”应表示 `not_started` 和 `inconclusive`，不能误判为负面效果。
- 计划是否可匹配动作取决于 SKU、操作类型、范围、动作日期、计划周期和生命周期状态，不能只查 `is_latest`。
