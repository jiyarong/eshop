# 06 库存概况与趋势

## 目标

沿用现有库存数据粒度，回答 SKU 总库存是否安全、库存分布在哪个平台和店铺，以及八周变化。不建设 Listing 级库存。

## 已冻结粒度

- 库存保持现有 `SKU + 平台 + 店铺/账号 + fulfillment_type` 粒度。
- 同一店铺同一内部 SKU 的多个 Listing 合并展示。
- `sku_product_id`、WB `nm_id`、Ozon `platform_sku_id` 不作为库存表或库存快照的新维度。
- 页面不得将店铺库存平均或按销量拆分给 Listing。

## 研发任务

1. 复用 `Ec::InventoryPageDetailQuery`、`Ec::SkuInventoryOverview` 展示采购中、账面可用、平台在库、FBS、预测日销量、周转天数、含采购周转天数。
2. 将“日均销量”展示名统一为“预测日销量”；查询返回 7/15/30 天销量、排除说明和最终预测的结构化解释。
3. 增加平台/店铺库存表：平台、店铺、FBS、FBO/FBW、在途、上周净销量、预测日销和覆盖天数。
4. 覆盖 = 可售/预测日销；含在途覆盖另列。账面可用等 SKU 共享库存只在 SKU 汇总展示。
5. 若某店铺绑定多个 Listing，在店铺行显示 Listing 数量和“库存已合并”说明；可展开查看绑定信息，但不展示虚构的 Listing 库存数值。
6. SKU 八周趋势读取 `Ec::Snapshot`；每周取周末最后有效快照，同周指标使用同一日期。运营事件通过 03 的公共 `events` target 与 `applyOperationEventMarkLines` 绘制竖线，06 不自行拼 ECharts `markLine`。
7. 如快照 content 已有可靠店铺维度，可展示店铺库存趋势；没有则只做 SKU 趋势，不修改库存同步和数据模型来追求 Listing 历史。
8. 保留待入库、账面可用、平台在库、退货子 Tab 和分页。

## 与 Listing 模块的关系

Listing 的上周销量、漏斗和 WR 利润放在对应业务模块中。库存页只可用这些指标辅助解释店铺库存，不将它们用于分摊库存。进入某 Listing 时，可以显示其所属店铺的合并库存，但必须明确标注粒度。

## 验收

- [ ] 预测解释与算法同源。
- [ ] SKU 总体、平台和店铺库存能够对账。
- [ ] 同店多 Listing 只产生一份店铺库存，页面有合并提示。
- [ ] 页面和接口不返回伪造的 Listing 库存或覆盖天数。
- [ ] 趋势只读真实快照，GET 不写库。
- [ ] 零日销、快照断档、周末缺失和多 Listing 店铺测试通过。
- [ ] 现有库存同步、数据模型和库存明细无结构性改造或回归。
