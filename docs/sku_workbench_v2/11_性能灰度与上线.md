# 11 性能灰度与上线

## 目标

建立跨模块发布门禁，验证性能、兼容、权限、数据一致性和回退能力。

## 门禁

1. 抽屉只加载 Header 和当前 Tab，查询无 Listing/周期/SKU N+1。
2. 四周期和八周趋势批量查询。
3. 单 Tab 服务端响应目标 P95 < 1.5 秒；重趋势 Frame P95 < 3 秒。
4. 缓存键含 SKU、周期、筛选和底层更新时间，并验证失效。
5. 整页、抽屉、Tab Frame、JSON、旧参数和所有现有抽屉入口回归通过。
6. 利润按 `WR Listing + 店铺未分配 = WSU 店铺合计`、`WSU 店铺合计 = WSU-DEEP SKU 总计` 对账；同名指标跨页面一致。
7. 无数据、零、零分母、平台不支持和查询失败可区分。
8. 查看、管理、附件、人工记录和跨 SKU 安全测试通过。

## 灰度

使用同一路由下的服务端 feature flag 或用户白名单，不建设长期 `/v2`。监控抽屉失败率、Tab 延迟、超时、无数据比例、WR Listing 无法归属量、利润对账差额和旧参数使用量。

建议先给少量内部运营用户开放，观察至少一个完整经营周，再扩大范围。全量后保留旧参数兼容一个发布周期。
