# 15 订单买家国家与自动回填机制

> 状态：已实现（2026-10-20），线上尚未回填，见第 5 节。
> 目的：给每个订单一个可靠的买家国家（`ec_orders.buyer_country`），供市场场景（俄罗斯 / 白俄 / 哈萨克斯坦…）的取数、销量统计和分仓共用，而不是每个查询各自去对统计订单、币种或城市。

## 1. 信号与优先级

| 平台 | 优先级 | 信号 | `buyer_country_source` |
|---|---|---|---|
| WB | 1 | 统计订单 `raw_wb_stats_orders.country_name`（按 srid 对应订单的 `external_order_id`） | `stats_order` |
| Ozon | 1 | 过账的目的集群 `financial_data.cluster_to`，国家取自 Ozon 自己的集群表 `raw_ozon_warehouse_clusters.country_name` | `ozon_cluster` |
| Ozon | 2 | 买家城市（订单的 `buyer_city`，或目的地表 `raw_ozon_posting_destinations.city`），查 `config/buyer_places.yml` | `city` |
| Ozon | 3 | 买家付款币种（BYN→BY，RUB→RU），弱兜底，可在配置里整体关闭 | `buyer_currency` |

- 值是 ISO 3166 两位代码（RU、BY、KZ、AM…），俄语国名到代码的映射在 `Ec::BuyerCountry::COUNTRY_CODES`。
- **不用的信号**：账务的 `report_type`（1 类装着所有非俄罗斯销售，还有所有取消包裹，多数是俄罗斯买家的）；Ozon 配送方式名后面的地名（那是 Ozon 的发货点，如「Старина」「Колодищи」，不是买家城市）；WB FBS 订单的 `buyer_city`（导入时写进去的是 `wb_office`，卖家侧的收货办事处，线上几乎全是「Минск」）；Ozon 目的地表的 `is_belarus`（靠一份 27 个城市的写死名单判断，`true` 可信，`false` 不能当「不是白俄」）。

## 2. 证据（线上，2026-10-20，只读统计）

- Ozon 集群：近 90 天 FBO 7,768 单、FBS 2,669 单，`cluster_to` 全部有值；全部 13,131 个履约单都有。币种是 BYN 的 1,111 个过账全在「Беларусь」集群，「Беларусь」集群里没有 RUB 的。Ozon 集群表带国家：Россия、Беларусь、Казахстан、Армения、Узбекистан。
- Ozon 城市：近 90 天 FBO 有城市的占 79.1%，FBS 95.2%；两个城市来源在 5,971 个两边都有的订单上没有不一致。同名城市：Дзержинск、Иваново、Кировск、Светлогорск 在俄罗斯和白俄都有（近 90 天里都同时有 RUB 和 BYN 的买家）。
- WB 统计订单：近 90 天已签收、已退回 100% 有国家，FBW 100%，FBS 88.5%（缺的是统计接口没列出的已取消、已发货 FBS 订单）。
- 币种不能当国家：以后别的市场也可能用卢布或白俄卢布计费。

## 3. 机制

- `Ec::BuyerCountry`：解析器。城市表里没有的城市是「未知」，不是「非白俄」；同名城市用币种在候选国家里挑，挑不出就留空；币种弱兜底只在没有集群、没有已知城市时用。
- `config/buyer_places.yml`：`settings`（币种兜底开关与映射）、`clusters`（Ozon 集群表没给国家的集群，人工确认，现为 Самара、Махачкала）、`cities`（929 个地名，由 `script/generate_buyer_places.rb` 根据 Ozon 集群给出的国家生成；同名城市写成列表）。新增城市只要重新跑脚本、看一眼 diff 再提交。
- `Ec::OrderBuyerCountryBackfill`：同一条逻辑三个入口，重复执行结果不变：
  - 导入钩子（`Ec::OrderImport::Wb` / `Ozon` 的 `call` 末尾）：近 3 天的订单；失败只记日志，不影响导入。
  - 每日追赶（`config/recurring.yml` 的 `ec_order_buyer_country_catchup`，每天 4:40）：近 120 天尚未由平台信号确定的订单，补上迟到的统计订单、集群、新增地名；同时补 WB 履约单里还空着的 `cluster_to`。汇总写进日志。
  - 一次性全量（不限日期）。
- 规则：订单的国家来自平台自己的信号（WB 统计订单、Ozon 集群）就算定了，不再看；之前只有较弱来源时，更强的来源可以替换它；较弱来源不能覆盖较强的；两个来源说法不一致只计数，不改值。
- 用 `update_all` 按集合更新，不触发回调，也不写操作日志（这是派生字段，每次运行的汇总里留痕）。
- 监控：`Ec::OrderBuyerCountryBackfill.coverage(days: 90)` 按平台、状态给出有国家的比例和平台信号的比例；汇总里的 `unmapped` 列出没人归类的国家、集群、城市。

## 4. 同时做的修正

- 分仓用的 `RawWb::OrderClusterResolver` 补上「Казахстан」集群（此前哈萨克斯坦、吉尔吉斯斯坦等国家的订单没有集群，按集群统计时被漏掉）。已有的 WB 履约单由 `fill_wb_clusters` 补写。吉尔吉斯斯坦、乌兹别克斯坦等还没有集群，需要时在 `REGION_CLUSTERS` 加一行。

## 5. 上线与回填步骤

1. 部署（会执行迁移 `AddBuyerCountrySourceToEcOrders`：新增 `buyer_country_source` 列和 `(platform, buyer_country)` 索引）。
2. 先看预估，不写库：`Ec::OrderBuyerCountryBackfill.run(dry_run: true)`。本地库（线上备份）的结果：WB 9,829 / 11,776 可补，其余没有统计订单；Ozon 12,657 / 12,657 全部由集群确定。
3. 确认后执行一次全量：`Ec::OrderBuyerCountryBackfill.run`，再 `Ec::OrderBuyerCountryBackfill.fill_wb_clusters`。线上用 `kamal app exec --reuse --roles web`（写库只在 web 容器里跑一次）。
4. 之后每天自动追赶，不需要再手动执行。

## 6. 还没做
