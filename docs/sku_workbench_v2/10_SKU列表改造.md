# 10 SKU 列表改造

## 目标

将列表改为异常发现入口，而非重复利润报表。此包独立实施，不阻塞抽屉首版。

## 研发任务

1. 搜索 SKU/SPU/中俄名称；筛选类目、SPU/SKU、Grade、Stage、开发、运营和诊断风险。
2. 复用类目、SPU/SKU、负责人 shared 组件和 concerns。
3. 身份区显示 SKU、名称、SPU、Grade/Stage、开发/运营。
4. 诊断标签置于负责人右侧，显示严重级别、48 小时 NEW/日期和详情；不做处理工作流。
5. 总库存显示可售、在途、预测日销、覆盖和预测解释。
6. 分仓按 WB/Ozon、FBO/FBW/FBS 展示并突出关键区域缺货；无法精确拆分需标记。
7. 上周财报显示净销量、利润、广告及占比、年化收益率、年化净利和环比。
8. 上周订单显示下单、签收、取消、退货、在途和配送时间，数量口径来自 00。
9. 行或 SKU 链接打开 V2 抽屉；标签和行内操作不得误触发。
10. 使用批量列表查询，禁止每 SKU 分别运行报表。

## 验收

- [ ] 筛选和负责人业务归属正确。
- [ ] “上周”统一为上一个完整自然周。
- [ ] 列表与详情同名指标可对账。
- [ ] 无按 SKU N+1 查询。
- [ ] 空数据、长名称、多标签、分页和移动布局稳定。
- [ ] 抽屉与诊断交互测试通过。
