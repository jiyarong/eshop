# 05 销售漏斗

## 目标

用统一口径判断 SKU 总漏斗，再定位具体 Listing 的流量或转化问题。

## 研发任务

1. 默认 `P0` 为最近一个完整自然周，并向前读取三个等长、不重叠周期 `P-1 / P-2 / P-3`；用户选择多个完整周时，四个周期保持等长。
2. SKU 四周期标准漏斗：访问、加购、加购率、下单、加购到下单率、成交、访问到成交率、净销量。
3. 加购率 = 加购/访问；加购到下单率 = 下单/加购；访问到成交率 = 成交/访问。
4. SKU 比例汇总各 Listing 分子分母后重算，只放跨平台可严格映射字段。
5. 店铺 / Listing 漏斗显示对齐后的公共字段和所有平台特有字段；默认展示全部正在经营店铺，按 `P-1` 净销量降序。
6. 选中店铺 / Listing 的日趋势默认八周和访问、加购率、加购到下单率；图表只查询选中 Listing 事件，并通过 03 的公共 `events` target 与 `applyOperationEventMarkLines` 绘制事件竖线，不在 05 内拼 ECharts `markLine`。
7. 店铺 / Listing 四周期明细使用独立 Turbo Frame 分阶段加载；选中店铺后再懒加载其唯一 Listing 的趋势和运营事件。
8. SKU 公共漏斗矩阵下方提供公共漏斗趋势，默认折叠，用户点击后切换展示/隐藏；趋势的运营事件标记不在 05 内实现，留给后续专项文档。

## SKU 公共漏斗口径

SKU 标准漏斗按“商品卡访问 -> 加购 -> 下单 -> 成交 -> 净销量”展示。WB 和 Ozon 先映射到一致的原始分子、分母，再汇总到内部 SKU；不得汇总或平均平台已计算的转化率。

| SKU 公共指标 | WB 来源 | Ozon 来源 | SKU 计算方式 |
| --- | --- | --- | --- |
| 商品卡访问 | `raw_wb_sales_funnel_daily.open_card` | `raw_ozon_sales_funnel_daily.hits_view_pdp` | 各 Listing 求和 |
| 加购 | `raw_wb_sales_funnel_daily.add_to_cart` | `raw_ozon_sales_funnel_daily.hits_tocart_pdp` | 各 Listing 求和 |
| 加购率 | `add_to_cart / open_card` | `hits_tocart_pdp / hits_view_pdp` | SKU 总加购 / SKU 总商品卡访问 |
| 下单 | `raw_wb_sales_funnel_daily.orders` | `raw_ozon_sales_funnel_daily.ordered_units` | 各 Listing 求和 |
| 加购到下单率 | `orders / add_to_cart` | `ordered_units / hits_tocart_pdp` | SKU 总下单 / SKU 总加购 |
| 成交 | 不直接使用 `buyouts` 作为公共口径 | 不直接使用 `delivered_units` 作为公共口径 | 按统一成交状态从硬关联订单计算 |
| 访问到成交率 | - | - | SKU 成交数 / SKU 总商品卡访问 |
| 净销量 | 不从日漏斗表直接提取 | 不从日漏斗表直接提取 | 按统一取消、退货口径从硬关联订单计算 |

### 映射约束

1. Ozon 的 SKU 公共“商品卡访问”使用详情页访问 `hits_view_pdp`，不使用总曝光 `hits_view` 或搜索/目录曝光 `hits_view_search`。
2. Ozon 的 SKU 公共“加购”使用详情页加购 `hits_tocart_pdp`，不使用包含其他来源的 `hits_tocart`，确保与商品卡访问的边界一致。
3. WB `orders` 与 Ozon `ordered_units` 暂映射为公共“下单”。实现前必须用真实多件订单样本确认 WB `orderCount` 的单位是商品件数，可与 Ozon `ordered_units` 严格合并；如果实际是订单数，则不得直接合并。
4. WB `buyouts` 与 Ozon `delivered_units` 的事件语义、日期归属和退货回冲规则可能不同，只作为 Listing 平台字段展示，不直接相加为 SKU 成交数。
5. SKU 成交和净销量必须从 `ec_sku_products` 硬关联到订单商品，同时限定平台、店铺和平台商品标识；不得使用 `ec_order_items.sku_code` 兜底，未绑定订单不进入汇总。
6. 平台不支持字段时返回“不适用”，支持但当期没有记录时返回“无数据”，分母为零时转化率返回“无法计算”；三种状态不得统一写成 `0`。

### 平台特有字段

Ozon 的总曝光、搜索/目录曝光、详情页点击率、平均搜索排名等，以及 WB 的收藏数、平台漏斗表内库存等，只在 Listing 层按平台展示，不进入 SKU 公共漏斗。

## 店铺 / Listing 漏斗

### 统计粒度

1. 当前业务中，同一店铺内同一 SKU 暂时只有一个 `Ec::SkuProduct`，因此页面将“平台 + 店铺 + Listing”作为一个展示单元，Listing 漏斗即当前的店铺漏斗。
2. 服务端仍使用 `sku_product_id` 或平台商品 ID 作为稳定键，不把“一店一 SKU 一 Listing”写成不可扩展的数据结构。
3. WB 通过 `Ec::SkuProduct.product_id = raw_wb_sales_funnel_daily.nm_id` 归属；Ozon 通过 `Ec::SkuProduct.platform_sku_id = raw_ozon_sales_funnel_daily.sku` 归属，并同时限定平台和店铺。
4. 未绑定的平台漏斗行不得归入其它店铺 / Listing，不使用内部 `sku_code` 或 `offer_id` 兜底。

### 与 SKU 公共漏斗的区别

SKU 公共漏斗只展示两平台能严格合并的字段。店铺 / Listing 漏斗使用另一套展示原则：

1. 先将两平台语义一致的字段对齐到同一列。
2. 无法严格对齐的字段全部保留为平台特有列，不为了表格简短而丢弃。
3. 表格使用稳定的跨平台字段全集；某平台不支持某字段时，对应单元格显示空值 `-`，不显示 `0`。
4. `0` 只表示平台支持该字段、当期有有效数据且结果确实为零。整个周期没有源记录时，该周期行应表示为“无数据”，不补一行全零。

### 店铺 / Listing 字段对齐

| 展示字段 | WB 来源/公式 | Ozon 来源/公式 | 展示类型 |
| --- | --- | --- | --- |
| 商品卡访问 | `open_card` | `hits_view_pdp` | 对齐公共列 |
| 加购 | `add_to_cart` | `hits_tocart_pdp` | 对齐公共列 |
| 加购率 | `add_to_cart / open_card` | `hits_tocart_pdp / hits_view_pdp` | 对齐公共列 |
| 下单 | `orders` | `ordered_units` | 对齐公共列；WB 单位确认见上文 |
| 加购到下单率 | `orders / add_to_cart` | `ordered_units / hits_tocart_pdp` | 对齐公共列 |
| 下单金额 | `orders_sum` | `revenue` | 对齐公共列，保留平台原币 |
| 平台成交/签收 | `buyouts` | `delivered_units` | 同一展示位置但标明平台语义，不用于跨平台 SKU 相加 |
| 成交 | 硬关联订单 | 硬关联订单 | 统一业务口径 |
| 访问到成交率 | `统一成交 / open_card` | `统一成交 / hits_view_pdp` | 统一业务口径 |
| 净销量 | 硬关联订单 | 硬关联订单 | 统一业务口径 |
| 取消数 | `cancel_count` | `cancellations` | 对齐公共列 |
| 店铺期末库存 | 周期结束日的 `Ec::InventorySnapshot` 店铺库存 | 周期结束日的 `Ec::InventorySnapshot` 店铺库存 | 内部补充的 Listing 公共列 |
| SKU 期末总库存 | 周期结束日的 `Ec::InventorySnapshot` `overview.book_stock` | 周期结束日的 `Ec::InventorySnapshot` `overview.book_stock` | 内部补充的 SKU 上下文列，不得按店铺求和 |
| 总曝光 | - | `hits_view` | Ozon 特有列 |
| 搜索/目录曝光 | - | `hits_view_search` | Ozon 特有列 |
| 详情页点击率 | - | `hits_view_pdp / hits_view_search` | Ozon 特有列 |
| 全来源加购 | - | `hits_tocart` | Ozon 特有列 |
| 搜索/目录加购 | - | `hits_tocart_search` | Ozon 特有列 |
| 平均搜索排名 | - | `position_category` | Ozon 特有列 |
| 退货数 | - | `returns_count` | Ozon 漏斗表特有列；统一净销量仍使用订单口径 |
| 成交金额 | `buyouts_sum` | - | WB 特有列 |
| 平台成交率 | `buyouts / orders` | - | WB 特有列 |
| 取消金额 | `cancel_sum` | - | WB 特有列 |
| 收藏数 | `add_to_wishlist` | - | WB 特有列 |
| WB 库存 | `stock_wb` | - | WB 特有列 |
| 卖家库存 | `stock_mp` | - | WB 特有列 |

Ozon `session_view` 属于访客/会话口径，与上述次数型商品卡漏斗不同。当产品需要“访客数”时可作为 Ozon 特有列展示，不与 WB `open_card` 对齐。广告占比等来自其它数据域的指标不进入店铺销售漏斗主表；期末库存虽然同样来自内部补充数据，但两平台口径一致且对判断店铺漏斗有直接价值，因此作为公共字段展示。

### 期末库存口径

1. 两平台的期末库存都不从销售漏斗日表读取，统一使用 `SalesFunnelReports::EndingInventoryQuery` 从 `Ec::InventorySnapshot` 按周期结束日查询。
2. `店铺期末库存` 只汇总当前店铺的 `fbo / fbw / fbs` 库存层级，是店铺 / Listing 粒度的可统一指标。
3. `SKU 期末总库存` 来自同日 SKU 快照的 `overview.book_stock`，在各店铺行显示时数值相同，只用作 SKU 总体上下文，不得再按店铺相加。
4. 每个 `P-3 / P-2 / P-1 / P0` 行使用本周期结束日的快照，不对周期内每日库存求和或平均。
5. 快照缺失时显示空值 `-`，不回退使用 WB 漏斗表的 `stock_wb / stock_mp`，也不用附近日期快照自动补齐，除非后续单独冻结容错规则。

## SKU 公共漏斗趋势

1. 公共漏斗趋势紧跟在 SKU 四周期公共漏斗矩阵下方，不放在店铺 / Listing 明细之后。
2. 区域默认折叠，页面只显示带明确展开状态的趋势标题和展开/收起控件；用户可重复切换显示和隐藏。
3. 首次展开时再通过独立 Turbo Frame 懒加载趋势数据；后续收起只隐藏已加载内容，再次展开不重复查询，除非公共周期已改变。
4. 趋势使用 SKU 公共漏斗的统一字段和公式，按 SKU 粒度汇总 WB 与 Ozon；不出现平台特有字段，不平均 Listing 比例。
5. 趋势以 `P0` 结束日为右边界，默认展示最近八个完整自然周；每个点仍以单周汇总，不因 `P0` 选择多周而改为多周一个点。
6. 可选指标为商品卡访问、加购、加购率、下单、加购到下单率、成交、访问到成交率和净销量；数量与比例使用分开 Y 轴。
7. 缺失周保留空数据断点，不补零连线；零分母转化率保持不可计算，不显示为 `0%`。
8. SKU 趋势的运营事件竖线属于后续专项范围。05 不查询事件、不构建 `events` 数据、不拼装 ECharts `markLine`，也不渲染无数据的事件占位。

### 公共周期与页面结构

本 Tab 的周期、四周期排列和店铺选择逻辑与 `04_利润归集分析.md` 保持一致：

1. 用户选中由一个或多个完整自然周组成的连续日期范围，该范围为 `P0`；默认 `P0` 为最近一个完整自然周。
2. 向前读取三个等长、不重叠周期 `P-1 / P-2 / P-3`。`P0` 如果选择两周，每个周期均为两周，四个周期总计覆盖连续八周。
3. SKU 公共漏斗和店铺 / Listing 漏斗共用同一 `P0`，不允许两部分处于不同周期。
4. 四周期从旧到新按 `P-3 -> P-2 -> P-1 -> P0` 展示；页面必须同时显示周期代号和真实起止日期。
5. 比例字段在每个店铺和每个周期内分别使用该周期汇总后的分子、分母重算，不平均周内日比例或平台返回比例。
6. 四周期数据使用一个连续范围批量读取并分桶，不得按店铺、周期或指标循环执行完整查询。

页面从上到下为：

```text
销售漏斗
|
+-- 1. 周期与 SKU 公共漏斗
|   +-- P-3 / P-2 / P-1 / P0 四周期矩阵
|   +-- SKU 公共漏斗趋势（默认折叠，展开后懒加载）
|
+-- 2. 店铺 / Listing 漏斗明细
|   +-- 每个店铺 / Listing 为一组
|   +-- 每组固定 P-3 / P-2 / P-1 / P0 四行
|   +-- 每行横向展示对齐后的公共字段和平台特有字段
|
+-- 3. 选中店铺 / Listing 日漏斗趋势
    +-- 默认最近八个完整自然周
    +-- 运营事件标记
```

### 店铺范围、排列与选择

1. 本期不提供独立 Listing 选择器，也不预留不可用控件。页面默认展示当前 SKU 的全部正在经营店铺。
2. “正在经营”沿用 04 的口径：`P0` 有平台库存、有有效成交或有有效访问，满足任一条即展示。
3. 店铺数量少，本期不提供额外的平台、店铺或 Listing 筛选器。点击店铺 / Listing 分组后，只切换下方趋势对象，不改变 SKU 汇总或其它店铺明细。
4. 店铺分组默认按 `P-1` 净销量降序，其次按平台和店铺名稳定排序；默认选中排名第一的店铺用于趋势。
5. 一个店铺 / Listing 固定占四行，识别列为平台 / 店铺、Listing、周期；平台 / 店铺和 Listing 在同组四行中使用纵向合并单元格或等效分组标题。
6. 指标使用横向宽表展示，固定左侧识别列并允许表格水平滚动；不通过隐藏平台特有列压缩宽度。
7. 原“首屏最多 10 个”仅能作为分阶段加载或分页阈值，不得静默截断第 11 个及之后的正在经营店铺。

## 验收

- [ ] SKU 转化率不是 Listing 转化率平均值。
- [ ] Listing 筛选不改变 SKU 汇总边界。
- [ ] 平台无字段、无数据、零分母可区分。
- [ ] 未绑定订单不进入成交和净销量。
- [ ] 对比期、平台差异、零访问和硬关联测试通过。
- [ ] 店铺 / Listing 表每个店铺固定展示 `P-3 -> P-2 -> P-1 -> P0` 四行，并显示真实日期。
- [ ] 两平台同义字段使用同一列，平台特有字段保留，不支持的单元格显示空值而不是 `0`。
- [ ] 选中店铺只切换下方趋势，不重算 SKU 漏斗或隐藏其它店铺明细。
- [ ] WB 和 Ozon 的店铺期末库存都从周期结束日的内部库存快照读取，快照缺失与真实零库存可区分。
- [ ] SKU 期末总库存不按店铺行重复求和。
- [ ] SKU 公共漏斗趋势位于公共漏斗矩阵下方，默认折叠，首次展开才加载，可重复展开和收起。
- [ ] SKU 公共漏斗趋势使用统一 SKU 口径重算比例，缺失周和零分母状态正确。
- [ ] 05 不为 SKU 公共漏斗趋势查询或渲染运营事件标记。
