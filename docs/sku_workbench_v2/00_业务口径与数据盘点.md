# 00 数据能力审计与研发基线

## 这项研发具体要做什么

本研发包不是开发页面，也不是召开口径确认会议。研发需要编写一个只读审计工具，用实际数据库数据验证后续模块依赖的关联和汇总链路，并提交审计结果。

完成后必须新增：

1. `script/audit_sku_workbench_v2.rb`：可通过 Rails runner 执行的只读审计脚本。
2. `docs/sku_workbench_v2/00_数据审计结果.md`：记录执行环境、时间、统计结果、异常样本和最终结论。
3. 对现有服务补充必要的自动测试；测试路径写入审计结果。

审计脚本不得修改数据、调用平台 API、触发同步或采集快照。

## 执行方式

建议命令：

```bash
bin/rails runner script/audit_sku_workbench_v2.rb
```

脚本输出 Markdown 或结构化文本，至少支持：

- `FROM_DATE`、`TO_DATE`：审计时间范围，默认最近 8 个完整自然周。
- `SKU_CODES`：可选 SKU 白名单；未传时审计全部有效 SKU。
- 输出全局汇总，并为异常项保留最多 20 个样本 ID。

不在脚本中写死店铺 ID、SKU 或统计日期。

## 任务 1：平台商品绑定完整性

### 实现

分别检查 WB 和 Ozon：

- `Ec::SkuProduct` 总数、有效店铺数、内部 SKU 数。
- 缺少 `sku` 关联、店铺关联或平台商品 ID 的数量。
- WB 相同 `store_id + product_id` 是否出现冲突。
- Ozon 相同 `store_id + platform_sku_id` 是否映射到多个内部 SKU。
- 一个 `store_id + sku_code` 绑定 0、1、多个 Listing 的分布。
- 订单、WR 原始利润行和漏斗行中存在平台商品 ID、但无法映射 `Ec::SkuProduct` 的数量。

### 输出

| 平台 | 数据集 | 总行数 | 已绑定 | 未绑定 | 冲突 | 绑定率 |
|---|---|---:|---:|---:|---:|---:|

另列异常样本：平台、店铺/账号、平台商品 ID、数据日期、无法映射原因。

### 阻塞规则

- 同一店铺、同一平台商品 ID 映射到多个内部 SKU：阻塞所有 Listing 级研发，先修绑定。
- WR 或漏斗存在未绑定行：不阻塞整体研发，但对应页面必须返回“未绑定”统计，不能静默归入 SKU。

## 任务 2：首次成交查询验证

### 实现

新增或复用一个只读查询，按项目订单硬关联规则计算每个 SKU 的首次成交时间：

- Ozon：`store_id + platform + platform_sku_id`。
- WB：`store_id + platform + product_id = order_items.platform_sku_id`。
- 禁止使用 `order_items.sku_code` 和 `offer_id` 兜底。
- 有效成交状态直接复用现有销量/利润统计认可的状态集合，禁止在生命周期模块另建一套状态。

脚本统计：有首次成交的 SKU 数、尚未成交的 SKU 数、仅存在取消订单的 SKU 数，以及最早/最晚首次成交日期。

### 自动测试

至少覆盖：

1. WB 和 Ozon 各一条正常硬关联订单。
2. `order_items.sku_code` 正确但没有商品绑定，不应计入。
3. `order_items.sku_code` 错误但硬关联正确，应计入。
4. 只有取消/无效订单时应为尚未成交。
5. 跨店铺相同平台商品 ID 不得串单。

### 阻塞规则

首次成交固定使用 `Ec::SkuDailySalesQuery` 口径：排除 `cancelled`、`returned`，等价纳入 `pending`、`processing`、`shipped`、`delivered`。若利润服务存在不同状态口径，审计结果记录差异，但生命周期仍以该固定口径投影。

## 任务 3：利润三级对账

### 实现

审计最近 4 个完整自然周。对每个平台至少选择以下样本：

- 5 个正常单 Listing SKU。
- 所有能找到的同店多 Listing SKU，最多 10 个。
- 5 个有未分配费用的 SKU/店铺。
- 5 个有退货或负利润的 SKU。

逐层计算并比较：

```text
WR Listing 明细 + WR 店铺未分配费用
= WSU 对应 SKU + 平台 + 店铺

全部 WSU 店铺行
= WSU-DEEP 对应 SKU
```

WR 审计键：

- WB：店铺 + `nm_id`，区域行先汇总到同一 `nm_id`。
- Ozon：店铺 + `ozon_sku_id`。

WSU 审计键：内部 SKU + 平台 + 店铺。同店多 Listing 必须合并成一行。

### 输出

| 周期 | SKU | 平台 | 店铺 | WR Listing 合计 | WR 未分配 | WSU | 差额 | WSU-DEEP | 差额原因 |
|---|---|---|---|---:|---:|---:|---:|---:|---|

金额比较使用明确的小数精度；仅舍入差异和真实业务差异分开统计。

### 阻塞规则

- WSU 同店同 SKU 输出多行且无法稳定合并：阻塞利润页面研发。
- 差额无法由未分配费用、汇率或舍入解释：阻塞对应平台上线。
- 可解释差额不阻塞，但页面和接口必须显式返回差异项。

## 任务 4：销售漏斗 Listing 映射验证

### 实现

审计最近 8 个完整自然周的日漏斗：

- WB 按 `account_id + nm_id + stat_date` 映射 `Ec::SkuProduct.product_id`。
- Ozon 按 `account_id + sku + stat_date` 映射 `Ec::SkuProduct.platform_sku_id`。
- 统计总行数、已绑定行、未绑定行、冲突行和缺失日期。
- 对同店多 Listing SKU，验证各 Listing 能分别得到访问、加购、下单/成交指标。
- 将 Listing 行重新汇总到 SKU，验证转化率由总分子、总分母重算，而非平均 Listing 比例。

### 输出

| 平台 | 日期范围 | 原始行 | 已映射 Listing | 未映射 | 冲突 | 有数据 Listing 数 | 缺失日期数 |
|---|---|---:|---:|---:|---:|---:|---:|

另输出至少一个同店多 Listing 的计算示例，包含各 Listing 分子分母、SKU 合计和重算比例。

### 阻塞规则

- 平台商品 ID 冲突映射：阻塞该平台 Listing 漏斗。
- 某日无平台原始数据属于数据空洞，不以零填充；页面需要返回缺失状态。

## 任务 5：库存现有粒度验证

### 实现

本任务不研究 Listing 库存拆分，只验证现有粒度能否稳定支撑页面：

- 按 `sku_code + platform + store/account + fulfillment_type` 统计最新库存。
- 验证同店同 SKU 多 Listing 最终只对应一组合并库存。
- 对比 `Ec::SkuInventoryLevel` 最新值、`Ec::InventorySnapshot` 最近日快照和现有库存详情查询的合计。
- 统计最近 8 周快照覆盖：应有天数、实际有天数、缺失日期、最晚快照日期。
- 抽样检查 FBS、FBO/FBW、inbound 和 `warehouse_breakdown` 能否按店铺展示。

### 输出

| SKU | 平台 | 店铺 | Listing 数 | FBS | FBO/FBW | 在途 | 最新同步 | 快照覆盖率 | 对账差额 |
|---|---|---|---:|---:|---:|---:|---|---:|---:|

### 阻塞规则

- 当前库存与最近快照存在无法解释的差异：不阻塞当前库存展示，但阻塞历史趋势。
- 同店多 Listing 不得在输出中复制库存；发现复制则阻塞库存页面研发。
- 快照缺日必须作为断档处理，不得自动补零。

## 任务 6：查询性能基线

### 实现

对上述审计查询记录：样本规模、SQL 数量、总耗时和最慢查询。至少测试：

- 单 SKU、单店多 Listing。
- 单 SKU、跨平台多店铺。
- 全量绑定覆盖统计。
- 4 周利润三级对账。
- 8 周漏斗和库存快照覆盖。

输出后续页面查询的基线，不要求本研发包完成所有性能优化；发现逐 Listing 或逐周循环完整报表时，必须在对应研发包登记重构任务。

## 审计结果文档固定结构

`00_数据审计结果.md` 必须包含：

1. 执行日期、环境、时间范围和代码 commit。
2. 数据规模摘要。
3. 六项任务的结果表。
4. 异常样本及原因。
5. 阻塞项清单，标明影响研发包编号。
6. 已接受的数据限制和页面降级方式。
7. 自动测试文件与测试命令。
8. 最终结论：00 是否完成，哪些后续研发包可以启动。

不得在结果文档中记录 API token、客户隐私字段或完整订单内容。

## 完成标准

- [ ] 只读审计脚本可重复执行，支持日期和 SKU 范围参数。
- [ ] 六项任务均有实际数据结果，不只描述表结构。
- [ ] 首次成交硬关联测试通过。
- [ ] WR、WSU、WSU-DEEP 有逐级对账结果。
- [ ] WB、Ozon 漏斗都有 Listing 映射覆盖统计。
- [ ] 库存已验证保持店铺粒度且没有重复分摊。
- [ ] 所有不可解释差异均形成明确阻塞项。
- [ ] 审计结果已回写主索引状态和相关研发包。
