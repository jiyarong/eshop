SKU经营分析工作台 V1.0 设计方案

一、定位
SKU经营分析工作台作为运营、产品日常管理SKU的核心入口。
目标：
一个页面查看SKU全部经营状态；
快速发现问题；
快速分析原因；
快速执行动作；
沉淀SKU历史经营记录；
逐步将人工巡检转化为系统自动巡检。

五、SKU详情经营页
页面结构
1. SKU经营摘要（首页）
固定展示。
基础信息： SKU、SPU、品类、生命周期、上架时间、负责人、当前经营状态
展示：
销售：最近销量、销售趋势
利润：收入、毛利、净利润
库存：可售库存、在途库存、周转天数
广告：花费、ACOS、广告订单占比
系统判断：
例如：当前SKU利润稳定，库存45天，无风险。
或者：当前利润下降，主要原因是广告成本上涨。
2. 销售分析Tab
内容：
销售趋势：日销量曲线、周销量趋势、环比变化
销售漏斗展示：曝光、点击、CTR、加购、转化率、订单
流量来源：自然流量、广告流量、推荐流量
区域销售：国家、城市、仓库区域
3. 广告分析Tab
内容：
广告效果：花费、广告销售额、ACOS、ROI、广告订单
趋势：广告成本变化、广告订单变化
异常分析：例如：花费增加但订单下降、ACOS提升、某关键词效率下降
4. 利润分析Tab
内容：
收益：销售额、毛利、净利润
成本结构：商品成本、物流成本、平台费用、广告费用、仓储费用
趋势：周利润变化、利润率变化
5. 库存分析Tab
内容：
当前库存：可售库存、在途库存、FBS/FBO库存、分仓库存
库存健康：周转天数、预计断货日期、预计积压日期
补货建议输出：是否补货、建议数量、建议时间
6. 生命周期分析Tab
展示：
当前阶段：NEW / GRW / MAT / CLR
阶段目标：例如：
NEW：是否完成测试、是否达到增长标准
GRW：是否持续增长、是否扩大库存
MAT：是否稳定盈利
CLR：是否按计划清仓
7. Event时间线
展示： SKU历史所有事件。
例如：2026-07-01
库存风险
原因：预计20天后断货
Action: 补货500件
结果：库存恢复
Event来源：
自动巡检
人工创建
AI分析
8. Action记录
运营填写：
Action内容自然语言：例如：“降低广告预算20%，观察ACOS变化”
记录：
时间
操作人
原因
预期结果
后续关联：
数据变化
结果验证

八、自动化演进
V1：人工查看 + 数据聚合
V2：自动巡检生成Event
例如：库存风险、销售异常、广告异常、利润异常
V3：AI辅助分析
自动：找原因、给建议、推荐Action
V4：成熟模块自动化
人工只处理：新问题、高价值问题、系统无法判断的问题
