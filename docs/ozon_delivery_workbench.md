# 送仓计划与打包批次

送仓工作台先选择 SKU，再指定店铺对应的目标集群及送仓周。缺货建议是选品参考，没有缺货的集群也可送仓；建立计划无需箱规或配送方式。

## 数量在打包阶段确定

- `Ec::DeliveryPlanItem.units` 为可空的正整数预估量。选择商品时不默认数量，可直接留空保存。
- 预估量不限制后续打包件数，可以调低、清空，也允许累计打包超过预估。实际批次数量仍受库存、完整箱规、供货 Listing 可确定性和箱/托容量校验。多个 Listing 时优先 active；多个 active 时选当前店铺中最近有订单的 Listing，订单时间不受销量日期或目标集群限制。无 active、active 均无订单或最近订单时间并列时仍提示无法确定。
- 有预估时，建议箱数参考扣除其他未取消批次后的预估待送量，整箱向上取整并受库存限制；无预估时参考销量。按比例增补和单 SKU MAX 不受覆盖天数或销量限制；MAX 保持其他 SKU 箱数及当前托数，按库存、剩余空间、重量和实际排布验算。手工改量不自动减量。
- 计划详情分别展示预估量、批次累计件数及预估待送量。累计包含草稿和已完成批次，排除取消批次；这不是已发货量。预估待送量最低显示 0，不能当作再次打包的硬上限。

## 数据与执行边界

- `Ec::DeliveryPlan` / `Ec::DeliveryPlanItem` 保存送仓意图，计划本身不占库存。
- `Ec::PalletPlan.delivery_plan_id` 可空，一份计划可以关联多个箱送或托送批次；历史独立批次继续可用。
- 每个执行批次只使用一种货位类型：普通 `BOX` 或普通 `PALLET`。实际打包、供货建单、状态回读沿用现有链路。
- 库存仅由既有 `COMMITTED_STATUSES` 批次占用，草稿只计入批次累计。运营创建新批次前应核对累计数量。
- 父计划修改、取消及批次保存使用父记录锁。仍被未取消批次使用的 SKU 不能从计划移除；有未取消批次时不能取消父计划。已有批次不可改挂其他计划。
- GET、计算预览和自动选品保持只读，不调用平台 API，不创建批次或占库存。页面保留 HTML 和 `.json`，并校验整份计划的 SKU 可见范围。

## 与任务 337 的衔接

当前未核实任务 337 的实际开发进度。本次拆分以现有普通箱送、托送批次为执行入口，保留 `delivery_plan_id` 作为衔接点。

跟进任务 337 时需核对：

1. “暗箱托盘”对应普通箱/托货位还是平台运输货位；不能将运输货位能力等同于普通 `BOX/PALLET`。
2. 外部或自动打包结果如何写入批次、保留 SKU 归属并更新累计件数。
3. 是否复用现有库存确认、取消及供货回读流程，避免在送仓计划层重复预留库存。
