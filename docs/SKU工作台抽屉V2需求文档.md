## 全局约束

1. 保留 `/reports/skus/:sku_code?tab=...`、Turbo 抽屉和 HTML/JSON 能力，不长期分叉 `/v2` 路由。
2. SKU 是汇总对象，`Ec::SkuProduct` 是 Listing，`Ec::OperationAction` 是运营事件主体。
3. 订单必须通过 `ec_sku_products` 按平台、店铺和平台商品 ID 硬关联；禁用 `order_items.sku_code`、`offer_id` 兜底。
4. 比例先汇总分子、分母再重算；零分母返回空值。
5. GET 只读，不调平台 API、不触发同步或快照。
6. 新 UI 使用 ERB + Turbo/Hotwire，复用 shared 组件，文案全部 I18n，时间使用用户时区。
7. 重计算进入查询对象，不在 ERB 或 Controller 拼业务指标。

## 已冻结的统计粒度

- 利润 WR：改造为店铺内 Listing 级，WB 使用 `nm_id`，Ozon 使用 `ozon_sku_id`；店铺未分配费用单列。
- 利润 WSU：保持 `SKU + 平台 + 店铺` 粒度；同店同 SKU 多 Listing 合并。
- 利润 WSU-DEEP：保持 SKU 总汇总粒度。
- 库存：保持现有 SKU/平台/店铺/履约方式粒度；同店同 SKU 多 Listing 合并，不建设 Listing 库存或 Listing 库存趋势。
- 销售漏斗和明确归属的运营动作：继续支持 Listing 粒度。

## 未决事项

由 00 负责确认：平均每单利润分母、履约指标按单还是件、月度首版范围、平台补贴公式。现有 WSU-DEEP 的 `average_profit_per_order` 实际使用净销量作为分母，名称与口径是否一致仍需冻结；生命周期的断货与恢复阈值已在 02 冻结。
